backtest-lib v0.1.0

Librairie locale pour le téléchargement de données crypto (ccxt + cache Feather), le backtest vectorisé (vectorbt) et l'analyse des résultats.

Installation

La librairie est installée en mode éditable depuis le répertoire source. Toute modification dans les fichiers source est immédiatement disponible sans réinstallation.

# Depuis le dossier du projet
pip install -e /home/faucheur/code/backtest

# Import dans n'importe quel script
from data_manager import DataManager
from backtest_vectorbt import TradingSimulator
from backtest_analysis import BacktestAnalyzer
Mode éditable (-e) pip pointe directement vers le dossier source. Pas besoin de réinstaller après chaque modification.

DataManager

class DataManager
from data_manager import DataManager

Gestionnaire de données OHLCV crypto via ccxt, avec cache local au format Feather (Apache Arrow). Il évite de re-télécharger les données déjà présentes en cache, et supporte la récupération incrémentale (seul l'intervalle manquant est téléchargé).

Initialise le gestionnaire et crée les dossiers de cache si nécessaire.

ParamètreTypeDescriptionDéfaut

data_dirstr Répertoire racine des données. Le cache est stocké dans data_dir/cache/. "data"

parse_duration static

DataManager.parse_duration(duration: str) → timedelta

Convertit une chaîne de durée en timedelta. Utilisé en interne par fetch_symbol et download_period.

Jours
"7j""14d""30day"
Semaines
"2w""4week"
Heures
"6h""48hour"
Mois / Ans
"3mois""1an""1y""2year"
Espaces tolérés partout Les espaces sont supprimés avant parsing : "30 d", "30d" et " 30d " sont équivalents.
Mois et années approximatifs 1 mois = 30 jours fixes, 1 an = 365 jours fixes. Pas de calcul calendaire (pas de prise en compte des années bissextiles ou des mois de 28/31 jours).

fetch_symbol

dm.fetch_symbol(symbol: str, timeframe: str, duration: str, ...) → DataFrame

Télécharge les données OHLCV pour les N dernières unités de temps à partir de maintenant. Utilise et met à jour le cache local automatiquement.

ParamètreTypeDescriptionDéfaut
symbol requisstr Paire de trading au format BASE/QUOTE, ex : "BTC/USDT". Doit être un marché spot actif sur l'exchange. —
timeframe requisstr Résolution des bougies selon la nomenclature ccxt : "1m", "5m", "15m", "1h", "4h", "1d"… Les timeframes valides dépendent de l'exchange. Sur Binance : "1m" à "1M" ; vérifier exchange.timeframes pour les autres exchanges. —
duration requisstr Durée à remonter depuis maintenant. Voir parse_duration pour les formats acceptés. —
exchange_override optionnelccxt.Exchange Instance ccxt alternative (utile pour les workers parallèles). Si omis, l'instance interne est utilisée. None
validate_symbol optionnelbool Active la validation du symbole sur l'exchange (appel réseau). Mettre à False si déjà validé en amont. True
Retourne
pd.DataFrame indexé par timestamp (DatetimeIndex UTC) avec les colonnes open, high, low, close, volume.

print(df.head())
Symboles spot uniquement La validation rejette les marchés futures/perpetual/swap. Utiliser uniquement des paires spot comme "ETH/USDT".

Limites et comportements à connaître

SujetComportement
Cache incrémental avec court-circuit Avant tout téléchargement, le programme vérifie si le cache couvre déjà la plage demandée (file présent + période couverte). Si oui, les données sont retournées directement sans appel réseau ni écriture disque. Sinon, seuls les intervalles manquants sont téléchargés. Si l'exchange corrige des données historiques, elles ne seront pas mises à jour automatiquement.
Cache partagé par (symbol, timeframe) Un seul fichier cache par paire (symbol, timeframe). Si des appels successifs couvrent des plages très différentes, tout l'historique connu s'accumule dans ce fichier.
Timeframes Délégués directement à ccxt. Les valeurs valides dépendent de l'exchange. Pour Binance : "1m", "3m", "5m", "15m", "30m", "1h", "2h", "4h", "6h", "8h", "12h", "1d", "3d", "1w", "1M". Consulter exchange.timeframes pour les autres exchanges.
Erreurs en mode parallèle Avec max_workers > 1, tous les symboles sont tentés avant de remonter les erreurs. Si au moins un symbole échoue, un RuntimeError est levé à la fin avec la liste des symboles en échec. Les symboles réussis sont perdus. Gérer l'exception si un comportement partiel est souhaité.
Barres de progression Les méthodes batch (download_period, download_range, load_or_download_range) affichent une barre de progression par symbole via tqdm. _download_chunk affiche une barre par page d'API (estimation). Les barres internes disparaissent après chaque symbole (leave=False).
Spot uniquement La validation refuse les marchés futures/perpetual/swap. Seules les paires spot sont acceptées (ex : "BTC/USDT", pas "BTC/USDT:USDT").
Limite API Chaque page de téléchargement est limitée à 1000 candles. Le nombre de pages dépend de la durée et du timeframe. Ex : 1 an de données en "1h" ≈ 9 pages.
Tolérance bougie en cours (fetch_symbol) Lors d'un appel par durée glissante (fetch_symbol), la bougie en cours de formation n'est pas encore fermée sur l'exchange. Le cache est considéré complet si son dernier timestamp est à moins d'un timeframe de l'instant présent, évitant un appel réseau inutile pour récupérer une bougie incomplète.

TradingSimulator

class TradingSimulator
from backtest_vectorbt import TradingSimulator

Moteur de backtest vectorisé basé sur vectorbt. Encapsule la construction du portefeuille, le calcul des métriques de performance (Sharpe, drawdown, beta, win rate…) et l'export des résultats. Conçu pour fonctionner avec un objet strategy qui expose les méthodes prepare_data et generate_signals.

TradingSimulator(config=None, strategy=None)

Initialise le simulateur. Les portfolios sérialisés (fichiers .pkl) sont stockés dans config.PORTFOLIO_DIR (défaut : backtests/portfolios/).

ParamètreTypeDescriptionDéfaut

  • PORTFOLIO_DIR: str — dossier de sauvegarde des portfolios
  • default_params: dict — paramètres par défaut (voir ci-dessous)

run_simulation

ts.run_simulation(symbol: str, data_dict: dict, params=None, reload=False) → dict

Lance la simulation pour un seul symbole. Si un fichier .pkl existe déjà pour ce symbole/stratégie et que reload=False, le portfolio est rechargé depuis le disque sans recalcul.

ParamètreTypeDescriptionDéfaut
symbol requisstrPaire de trading, ex : "BTC/USDT".—
data_dict requisdictDictionnaire {symbol: DataFrame} retourné par DataManager.—
params optionneldictRemplace config.default_params. Voir la structure ci-dessus.None
reload optionnelboolSi True, force le recalcul même si un .pkl existe.False
Retourne
{"symbol": str, "portfolio_data": dict} où portfolio_data contient :
  • final_value, total_profit, total_return
  • annualized_return, sharpe_ratio, beta_underlying
  • max_drawdown, win_rate, trade_count
  • equity_curve : pd.Series de la valeur du portefeuille dans le temps
  • portfolio_path : chemin du fichier .pkl sauvegardé

run_batch_simulations

ts.run_batch_simulations(symbols: List[str], data_dict: dict, params=None, reload=False) → Tuple[dict, dict]

Lance les simulations en parallèle sur tous les symboles via ProcessPoolExecutor (18 workers hardcodés). Les erreurs par symbole sont catchées et loggées sans interrompre le batch.

Attention — ProcessPoolExecutor Le code de la stratégie et du config doit être picklable (pas de lambdas, pas de closures non sérialisables). Ce point d'entrée est conçu pour des runs sur un grand nombre de symboles (20+).
Retourne
(results, portfolios_data) — deux dicts avec le symbole comme clé. portfolios_data est directement passable à export_results_to_json. 
results, portfolios_data = ts.run_batch_simulations(
    symbols, data_dict, params=params, reload=False
)
ts.export_results_to_json(portfolios_data, symbols)

Quickstart complet

from data_manager import DataManager
from backtest_vectorbt import TradingSimulator
from backtest_analysis import BacktestAnalyzer

# 1. Télécharger les données
dm = DataManager("binance", "./data")
symbols = ["BTC/USDT", "ETH/USDT", "SOL/USDT"]
data_dict = dm.download_period(symbols, "1h", "3mois", max_workers=3)

# 2. Configurer la simulation
class Config:
    PORTFOLIO_DIR = "backtests/portfolios"
    default_params = {
        "capital_initial": 10_000,
        "fees": 0.001,
        "slippage_base": 0.0,
        "timeframe": "1h",
    }

ts = TradingSimulator(config=Config(), strategy=my_strategy)

# 3. Lancer le backtest
results, portfolios_data = ts.run_batch_simulations(symbols, data_dict)

# 4. Exporter les résultats
output = "backtests/results/results.json"
ts.export_results_to_json(portfolios_data, symbols, output_path=output)

# 5. Analyser et générer les graphiques
analyzer = BacktestAnalyzer(summary_path=output)
stats = analyzer.run()

Écrire une stratégie compatible

TradingSimulator délègue la préparation des données et la génération des signaux à un objet strategy. Celui-ci doit implémenter deux méthodes :

Interface attendue

class MyStrategy:
    name = "MyStrategy"  # Utilisé pour nommer les fichiers .pkl

    def prepare_data(self, data_dict: dict, symbol: str):
        """
        Prépare et enrichit le DataFrame pour un symbole donné.

        Paramètres :
          data_dict : dict {symbol: DataFrame} retourné par DataManager
          symbol    : paire courante ex "BTC/USDT"

        Doit retourner : (data, asset_name)
          data       : pd.DataFrame avec au moins une colonne nommée asset_name
          asset_name : str, nom de la colonne prix (ex "BTC")
        """
        df = data_dict[symbol].copy()
        asset_name = symbol.split("/")[0]
        df[asset_name] = df["close"]
        return df, asset_name

    def generate_signals(self, data: pd.DataFrame, asset_name: str, params: dict):
        """
        Génère les signaux d'entrée/sortie.

        Doit retourner un tuple de 3 ou 5 éléments :
          (data, entries, exits)                              — long only
          (data, entries, exits, short_entries, short_exits)  — long + short

        entries / exits : pd.Series ou pd.DataFrame de booléens,
                          indexés comme data.
        """
        close = data[asset_name]
        sma20 = close.rolling(20).mean()
        sma50 = close.rolling(50).mean()

        entries = (sma20 > sma50) & (sma20.shift(1) <= sma50.shift(1))
        exits   = (sma20 < sma50) & (sma20.shift(1) >= sma50.shift(1))

        return data, entries, exits
Convention de nommage des colonnes Le simulateur cherche une colonne dont le nom est asset_name (ex : "BTC") dans le DataFrame. Si elle est absente, il replie sur "close". Assure-toi que prepare_data crée cette colonne.
Signaux booléens entries et exits peuvent être des pd.Series, pd.DataFrame ou des arrays numpy. La méthode interne _to_bool_frame les normalise automatiquement.
